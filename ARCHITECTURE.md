# Архитектура `idea-to-code-bot`

Документ описывает архитектурные решения, текущее состояние, стек и решённые технические проблемы.

---

## Концепция

Личный Telegram-ассистент: со смартфона командуешь ботом → бот обрабатывает на ПК (где есть Claude API) → возвращает результат файлом/ZIP.

Конвейер:
1. Пользователь кидает идею в свободной форме
2. Бот строит структурированный план (обзор + детальный по кнопке)
3. Если в плане есть развилки требующие решения — спрашивает кнопками
4. Разносит план по «отделам» (КОД / ДИЗАЙН / МУЗЫКА / НАПОЛНЕНИЕ / ПРЕДЛОЖЕНИЯ / ДРУГИЕ)
5. По кнопке «▶️ Выполнить» исполняет отдел → файл/ZIP результата

---

## Архитектурные решения

### Один бот вместо нескольких

Изначально была идея «несколько ботов в команде» (каждый со своей ролью, общающиеся между собой). Отказался: для соло-пользователя межпроцессное общение между Telegram-ботами — лишний геморрой без видимой пользы.

**Принято:** один процесс с несколькими режимами/ролями внутри. Разные system prompts (`PLAN_SYSTEM`, `EXEC_ROLES`) активируются в зависимости от фазы конвейера.

### Изолированный LLM-слой

Все вызовы Claude API собраны в отдельных функциях с явными сигнатурами:

| Функция | Что делает |
|---|---|
| `generate_plan(idea, previous_attempt=None)` | Возвращает `(обзор, полный план)`, разделитель `===ПОДРОБНО===` |
| `edit_plan(full, edit_request)` | Точечные правки к плану по тексту запроса |
| `extract_decisions(plan)` | Вытаскивает развилки (`===РЕШЕНИЕ===`) → `[{q, opts}]` |
| `explain_options(q, opts, plan)` / `auto_pick(q, opts, plan)` | Объяснить варианты / выбрать автоматически |
| `categorize_plan(plan, qa)` | Разнос плана по отделам с учётом принятых решений |
| `execute_department(name, brief, feedback=None)` | Исполнение отдела → текст результата |
| `summarize_result(department, full)` | Короткая сводка для чата |

Хендлеры aiogram, FSM и кнопки про модель ничего не знают — можно подменить провайдера без правок UI. Если `PROXYAPI_KEY` и `ANTHROPIC_KEY` оба пусты, `HAS_LLM=False` и бот переходит в заглушечный режим (для отладки UI без сжигания токенов).

### Состояние: FSM + кнопки-команды для устойчивости

aiogram MemoryStorage in-memory → состояние теряется при рестарте бота. Решение:

- **Кнопки `restart` / `projects` / `proj:<id>` работают БЕЗ фильтра состояния.** Даже если FSM сброшен, переключиться между проектами или начать новую идею можно.
- **`cb_stale` ловит устаревшие колбэки** от кнопок прошлой сессии — отвечает информационным алертом, не пропускает в обработчики.
- Для прода полная персистентность (SQLite/Redis) — в бэклоге.

### Файловая система как «отделы»

Каждая одобренная идея = папка `projects/<дата>_<идея>/` со структурой:

```
projects/2026-05-18_змейка-неон/
├── _ИДЕЯ.txt
├── _ПЛАН.md
├── _РЕШЕНИЯ.md
├── КОД.md             # ТЗ для отдела
├── КОД_РЕЗУЛЬТАТ.md   # результат исполнения (или ZIP)
├── ДИЗАЙН.md
├── НАПОЛНЕНИЕ.md
└── ...
```

Просто файлы — не отдельные процессы и не БД. Каркас под будущее расширение, но без преждевременной сложности.

### Парсинг результата КОДа

`extract_code_files()` парсит ```-блоки из ответа модели → восстанавливает реальные файлы → собирает ZIP с `_ПОЛНЫЙ_ОТВЕТ.md` внутри. Если в ответе нет распознаваемых блоков — отдаём `.md` целиком, не теряем работу модели.

### Известное ограничение

Движок = только текстовый Claude. НЕ может: генерить PNG/картинки, MP3/аудио, собирать и запускать приложения. ДИЗАЙН/МУЗЫКА отделы возвращают текстовый бриф со спецификацией и ссылками на инструменты (BeepBox, sfxr, и т.д.). Реальная генерация ассетов через image/audio API — в бэклоге.

## Решённые технические проблемы

### 1. Telegram API заблокирован в РФ

`api.telegram.org:443` не доступен напрямую с российских IP. Два режима работы:

- **TUN-режим VPN (рекомендуемый):** VPN заворачивает весь системный трафик на уровне ОС. В `.env` `PROXY_URL` оставляется пустым, бот ходит «напрямую», VPN заворачивает прозрачно.
- **HTTP-прокси (fallback):** v2RayTun поднимает локальный HTTP-порт (например `127.0.0.1:12334`). В `.env` указывается `PROXY_URL=http://127.0.0.1:12334`, в `bot.py` `AiohttpSession(proxy=PROXY_URL)` передаётся в `Bot(...)`.

Проверка актуального порта v2RayTun:
```powershell
Get-NetTCPConnection -State Listen | Where-Object {(Get-Process -Id $_.OwningProcess -ErrorAction SilentlyContinue).Name -eq 'v2RayTun'} | Select LocalPort
```

### 2. Anthropic не принимает российские карты

Прямая оплата Anthropic API из РФ невозможна. OpenRouter требует крипту. **Решение:** [proxyapi.ru](https://proxyapi.ru) — российский посредник:

- Формат API идентичен Anthropic → официальный SDK работает с подменой `base_url`
- Принимает рублёвые карты напрямую
- Работает с РФ-IP без VPN
- Ключ в `.env` → `PROXYAPI_KEY`

```python
from anthropic import Anthropic
client = Anthropic(
    api_key=os.getenv("PROXYAPI_KEY"),
    base_url="https://api.proxyapi.ru/anthropic"
)
```

### 3. Обработка пустого баланса proxyapi.ru

При нулевом балансе API возвращает HTTP 402 `Insufficient balance`. Раньше бот падал → теперь `execute_department()` и др. ловят ошибку, возвращают её текстом. План пользователя не теряется, можно пополнить баланс и нажать «Переделать».

Кнопка «Переделать» по КОДу жжёт `max_tokens=20000` — самый дорогой вызов. Пользователь предупреждается.

### 4. FSM теряется при рестарте

Описано выше: ключевые кнопки работают БЕЗ фильтра состояния, `cb_stale` ловит висящие колбэки. Полная персистентность (SQLite) — в бэклоге.

### 5. VS Code Claude Code extension игнорирует `http.proxy` из настроек

Extension использует Node.js fetch, который не читает `http.proxy` из `settings.json`. Решение: запускать VS Code через `.bat` с env-переменной `HTTPS_PROXY`. Альтернатива — TUN-режим VPN.

### 6. `pygame` не собирается на Python 3.14

При генерации игр КОД-отдел инструктируется использовать **`pygame-ce`** (community edition) — обычный `pygame` требует C++ build tools на Python 3.14 и часто не собирается. Это записано в системном промпте `EXEC_ROLES["КОД"]`.

### 7. Сгенерированный `build.bat` жёстко требует assets/icon

При сборке `.exe` через PyInstaller автогенерированный `build.bat` ссылается на `--add-data` и `--icon` для несуществующих файлов. Решение — собирать вручную упрощённой командой:

```powershell
python -m PyInstaller --onefile --noconsole main.py
```

## Бэклог

- **Персистентность FSM** — SQLite вместо MemoryStorage. Низкий приоритет, есть workaround через кнопки-команды.
- **Генерация ассетов** — image API (Replicate / DALL-E / Stable Diffusion) для отдела ДИЗАЙН, audio API для МУЗЫКА. Требует решения по бюджету.
- **Telegram Mini App** — веб-интерфейс с проектами. Большой отдельный проект: фронтенд + публичный HTTPS-хостинг + мини-API. Mini App = витрина, возможностей не добавляет, поэтому отложено.
- **Кнопка «Выполнить всё»** — пакетное исполнение всех отделов проекта.
- **Просмотр готовых `*_РЕЗУЛЬТАТ.md`** в боте без выхода в файловую систему.
